Pagnetic Shopify review remediation evidence, recorded September seventh, twenty twenty-six after deployment of the authentication repair. This is a narrated sequence of current post-fix screenshots, not a continuous live screen recording. The screenshots were captured from the owned development store inside Shopify Admin after the production repair was deployed. No reviewer-store data, session token, credential, or private URL is shown.

Shopify reported that the embedded app area could become blank and ultimately return Application Error with an HTTP five hundred response. Production investigation confirmed a failure in the expiring offline-token lifecycle. When Shopify delivered uninstall and privacy webhooks after an offline refresh credential had been revoked, the framework tried to refresh that credential before running our cleanup handler. The refresh failed with an HTTP five hundred response, so stale sessions could remain. A later embedded request could encounter the same invalid refresh state.

The deployed repair preserves Shopify authentication and its expiring offline-token requirement. Uninstall and mandatory privacy webhooks now validate Shopify's signature over the exact raw request body without requiring an Admin API session. A missing or invalid signature is still rejected. These cleanup handlers do not call the Admin API, so they no longer depend on a token that Shopify has already revoked.

Embedded Admin requests now have one narrowly bounded recovery path. Recovery is considered only after the normal Shopify authenticator returns HTTP five hundred. The request must contain a cryptographically valid Shopify session token. The signed destination must identify the same shop as the stored offline session. That stored session must already be expired and contain refresh credentials. Pagnetic then deletes only the exact stale credential version it observed and retries normal Shopify authentication once. Invalid session tokens and unrelated errors are not bypassed, concurrent fresh credentials are preserved, and a second failed retry propagates.

Before this capture, we ran a controlled recovery test on our own development store. We changed only that store's offline credential to expired invalid test markers, then opened Pagnetic through a fresh Shopify Admin embedded request. The request returned HTTP two hundred, Shopify token exchange replaced both markers with new expiring credentials, and the full interface rendered. This was not performed on, and does not claim access to, Shopify's reviewer store.
